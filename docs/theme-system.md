# 主题系统设计与实现边界

> 设计记录：2026-08-31  
> 当前状态：主题画廊、分页、宝石/动物/水果/甜点/太空/海洋/春天/节日限定/音乐/交通工具 manifest 与棋盘渲染已接入；十套非经典主题已完成主体重提取并替换为标准精灵表，运行时缩放基线统一为 `1`。尺寸、槽位与透明安全边已有自动校验，模拟器/真机的最终视觉验收仍待进行。

## 1. 需求解释与现有主页基线

主题系统的原始需求分成两个阶段；当前主题页由回廊作为上游入口，主题自身协议仍沿用本文件。

1. 在主页/回廊链路中提供一个“主题”入口（当前由主页“回廊”按钮进入）。
2. 增加主题浏览/切换界面：每页固定 2 列 × 3 行，共展示 6 个主题，左右滑动切换页面；之后再制作第一个主题。

附件图片按用户说明作为**现有主页的视觉基线**记录。它约束的是当前风格方向：橙色背景、顶部音效入口、中央 Logo/完成信息、圆角白色层级按钮。图片中的“已完成 38 / 152”等数字是历史截图里的运行时示例，不得硬编码，也不是新的功能指令；当前普通关卡总数为 92。

当前实际发布入口是 `game.js → src/bootstrap.js → src/app.js → src/ui/canvas-renderer.js` 的微信小游戏 Canvas 运行时。`pages/*`、根目录 `app.js/app.json/app.wxss` 已在 `project.config.json` 中排除，只作为迁移参考；主题功能不写入这些旧页面。

回廊与消除特效的导航及首页入口迁移契约另见
[`docs/corridor-and-clear-effects.md`](corridor-and-clear-effects.md)。当前运行时已由 `home:corridor` 作为可见入口，`home:themes` 仅保留兼容 action；主题 manifest、`scene === 'themes'` 和 `theme:<id>` 协议不因回廊设计而改变。

## 2. 目标、范围与非目标

### 2.1 v1 目标

- 回廊中提供“主题”入口；主页当前由“回廊”按钮进入该功能。主题 manifest、画廊和每日挑战的独立契约不因此改变，主页迁移细节详见 [`docs/corridor-and-clear-effects.md`](corridor-and-clear-effects.md)。
- 新增主题画廊场景，可从回廊进入并按来源返回；旧 `home:themes` 直达流程仍兼容。
- 画廊按注册顺序分页，每页 6 张卡片（2 列、3 行）；不足 6 张时保留空槽，空槽不可点击。
- 支持左右横向滑动切页；在首尾页继续向外滑动不越界。
- 点击主题后，classic 或本进程已加载主题立即应用；未加载主题先下载对应普通分包，成功后才应用并持久化。重启后异步恢复上次选择。
- 主题资源缺失、加载失败或主题 ID 失效时，仍能用经典色块正常游戏。
- 在不改连线规则的前提下，为后续宝石、食物、植物、卡通等主题提供可扩展的声明式资源协议。

首个主题的默认覆盖层是**棋盘 tile 层**（普通格、同色端点、选中态、提示态和清除动画的外观）。主页背景、按钮、音效和其他 shell 视觉继续使用 classic 语义 token；只有在后续视觉需求单独确认后，manifest 才可覆盖 shell token。

### 2.2 明确不做

- 主题系统不改变 `core/game-runner.js` 的普通连通、阻挡、撤销、计时或完成判定。
- 说明：每日挑战为独立模式，现已为通用 `GameRunner` 增加可选 `blocked` 配置；该扩展不由主题系统启用，也不改变普通关卡的默认行为。详见 [`docs/daily-challenge-mode.md`](daily-challenge-mode.md)。
- 主题功能本身不修改关卡规则；关卡数量调整属于独立的数据变更，`data/clearedset5/6` 与对应提示表必须保持同步，颜色身份和路径解法不变。
- 不把主题判断、绘图回调或图片加载塞进规则层。
- 不在本阶段重命名现有 `SkinService`、`src/skins` 或存档字段 `settings.skinId`，也不升存档 schema。
- 主题 manifest 本身不承载解锁、付费、网络存档同步、主题编辑器或 CDN；本地奖励／货币由独立 RewardUnlockService 提供，正式素材仍通过微信普通分包按需加载。
- 不以修改旧 `pages/*` 为实现路径。

## 4. 用户流程与页面契约

### 4.1 主页

- 当前可见入口为 `home:corridor`，显示文案“回廊”；`home:themes` 仍保留为兼容 action，但不注册为首页 visible hit。
- `home:dailyChallenge`、`home:corridor` 和 `home:start` 是当前主页可见命中 ID；“选择关卡”按钮已移除。`home:levels`、`home:themes` action 暂保留给兼容调用，主页不注册这些旧命中区域。
- 三个主按钮沿用现有高度和圆角，使用 `safeBottom` 重新计算位置：第一行是并列的“高难关卡”和“回廊”，第二行是占满整行的“继续游戏/开始游戏”。`home:dailyChallenge` 的模式契约详见每日挑战文档。
- 三个按钮使用同一组主按钮背景/描边 token；“回廊”复用原主题按钮的位置和层级。
- 顶部音效按钮、Logo、完成数和背景语义色保持现有主题 token 驱动。

### 4.2 主题画廊

- 新增场景名：`scene === 'themes'`。
- 进入时默认显示第 0 页；回廊来源返回命中 ID 为 `themes:corridor`，旧直达流程继续使用 `themes:home`。
- 主题页返回/音效两个顶部 UI 按钮的中心使用 `layout.themesTopUiOffset` 下移 16px；返回按钮使用左箭头，围绕原中心将触摸区域从 44×44 扩大为 56×56，图标随之放大。音效按钮、标题、页码和卡片网格位置保持原布局；扩大后的返回区域仍与卡片网格分离。
- 每张有效卡片显示：主题的前 4 个元素按 2×2 排列（无 tile 素材时回退为 2×2 色块）、主题名（manifest 的 `name`）和当前选中态；不显示分类副标题。
- 分包未加载时读取主包 PNG-8 四格预览，不读取正式精灵表；卡片状态为 `idle`“点击下载”、`loading`“下载 N%”、`failed`“加载失败，点击重试”。预览在各下载状态下保持可见，成功后更新选中态。下载不会阻断分页、返回和游戏。
- manifest 顶层 `preview` 指向 `assets/theme-previews/<id>.png`：严格 128×128、最多 128 种实际 RGBA 颜色、每张不超过 8 KiB。每格为 64×64，预览仅用于画廊；失败时回退至已就绪正式图，再回退色块。详见 [`corridor-preview-assets.md`](corridor-preview-assets.md)。
- 卡片命中 ID：`theme:<id>`；空槽不注册命中区域。
- 点击有效卡片后调用统一的主题选择入口，立即重绘并留在当前页；用户通过“返回”回到回廊或主页（取决于进入来源）。
- `classic` 始终可用；其余主题按奖励目录初始锁定。锁定卡片仍显示主包预览与具体条件；只有永久拥有后才能下载正式分包并应用。拥有、当前应用和素材下载是三个独立状态，详见 [`reward-unlock-system.md`](reward-unlock-system.md)。
- 为复用关卡页的可发现性，左右箭头可作为滑动的辅助入口，使用 `themes:prev` / `themes:next`；若最终视觉稿隐藏箭头，分页状态机和滑动契约不变。

## 5. 分页、布局与触摸规则

分页常量固定，不与普通选关页的 `levelPageIndex` 混用：

```text
PAGE_SIZE = 6
COLUMNS = 2
ROWS = 3
pageCount = max(1, ceil(themeCount / PAGE_SIZE))
pageIndex = clamp(pageIndex, 0, pageCount - 1)
slotIndex = pageIndex * PAGE_SIZE + row * COLUMNS + column
```

布局必须使用 `safeTop/safeBottom` 和屏幕宽高动态计算；保持两列三行，不因窄屏改成单列。卡片尺寸、2×2 元素预览的间距与裁切属于渲染层参数，不进入主题 manifest 的业务逻辑。

滑动只在 `themes` 场景生效：

- 横向位移 `abs(dx) > 52` 且 `abs(dx) > abs(dy) * 1.2` 才算翻页。
- 手指向左（`dx < 0`）进入下一页，向右进入上一页。
- 首页向右、末页向左均保持原页，不产生越界或主题选择。
- 未达到阈值的拖动视为点击候选；垂直拖动不翻页。
- 主题画廊的 `pageIndex` 独立于普通选关页的 `levelPageIndex`，避免两个场景共享状态造成误切页。

## 6. 主题 Manifest 与资源协议

主题 manifest 必须是可序列化的声明式数据，不允许放绘图函数、触摸回调、网络请求或对 `GameRunner` 的引用。拟定字段如下：

| 字段 | 必需 | 用途与约束 |
| --- | --- | --- |
| `id` | 是 | 稳定、唯一、建议小写 kebab-case；一经发布不复用 |
| `name` | 是 | 画廊显示名；缺失时回退到 `id` |
| `category` | 否 | 宝石/食物/植物/卡通等筛选或展示标签，v1 不做筛选 |
| `sort` | 否 | 明确排序时使用；未提供则按注册顺序 |
| `preview` | 图片主题发布必需 | 主包 128×128 / 128 色 PNG-8 四格预览路径；经典主题可省略 |
| `assets` | 否 | Logo、主题 tile 或按颜色变体映射；路径相对项目根目录 |
| `tileVisuals` | 否 | 色块的声明式外观、变体与回退颜色；不改变格子几何 |
| `colors` | 否 | 背景、文字、面板、按钮等 shell 语义 token；首个主题默认不覆盖，缺失 token 继承 classic |
| `layout` | 否 | 仅放通用尺寸/动画所需的有限 token；不得改变触摸索引 |
| `animation` | 否 | 进入、清除、结果等时长 token；缺失值继承 classic |
| `setStyles` | 否 | 现有按关卡组的背景/调色板覆盖；调色板仍只表示颜色身份 |

`tileVisuals` 的实现约束：

- 主题可以用图片、纯色或两者回退来替换色块；每个变体必须有可用的回退颜色或明确使用关卡 palette。
- 首个主题至少覆盖棋盘 tile 层；不得因为提供 tile 素材而隐式改变主页背景、按钮或音效。
- 图片主题必须先绘制棋盘的半透明方形底砖，再叠加透明主题图；底砖默认复用 `colors.emptyCell`，不能被端点 palette 颜色替换成不透明色块。
- 图片变体的显示缩放由 manifest 的 `tileVisuals.scale` 控制；只调整视觉尺寸，不调整棋盘 cell、命中区域或触摸索引。
- `lineIndex → 主题变体` 必须是确定性的；变体不足时按约定回退，不改变同色端点配对。
- 空格、选中、固定端点、提示路径和清除动画都通过同一个 renderer 适配器绘制，保持状态差异只来自通用状态参数。
- 主题不提供连接线算法；路径顺序、相邻判定、提示路径和淡出时机仍由现有规则/编排数据驱动。
- manifest 不可注入任意代码；资源加载失败不能阻塞进入关卡。

### 6.1 色块变体数量（已按现有关卡核对）

主题需要按“逻辑色槽”提供变体，而不是按某一个关卡单独出图。普通关卡虽已限制到 8×8，但每日挑战仍包含 8×10；当前所有内容来源的最大 palette 如下：

| 内容来源 | 色槽数 |
| --- | ---: |
| 普通第 1—2 关（训练题面） | 2 |
| 普通 5×5、6×6、7×7 | 8 |
| 普通 8×8、每日 8×10 | 10 |

因此，一个要覆盖全部普通与每日关卡的完整主题仍需要 **10 个可辨识的色块变体**，每个变体对应一个 palette slot。实现上有两种等价交付方式：

- 10 张独立的色块图；或
- 1 张包含 10 个统一尺寸帧的 sprite sheet，由 renderer 切帧。

这 10 个是“逻辑图数量”，不要求必须是 10 个文件。训练关实际只会用其中 2 个，缺少变体时可以回退经典色块，但会被视为主题资源未完整覆盖。

主题画廊从正式图前 4 个 tile 离线生成独立的 128×128 / 128 色 PNG-8，按 2×2 切帧绘制。
主包小图位于 `assets/theme-previews/<id>.png`，不放进各主题分包；正式精灵表的 2000×800、10 槽合同不变。
运行时用临时预览配置复用 `drawTile()`，不修改已注册 manifest 或棋盘图片缓存。
选中、提示、清除淡出等状态不另做图片，由通用 renderer 通过缩放、透明度和叠加处理。

资源目录约定（内部兼容命名）：

```text
assets/skins/<theme-id>/
  tile-*.png           # 色块/变体素材（可选）
  ...                  # 其他主题专属图片
```

已有 `assets/logo.png` 和经典资源不在本阶段搬迁。非经典主题图片必须遵守下一节的固定精灵表规格；不能再使用无法整除的近似尺寸或依靠运行时缩小来隐藏跨槽像素。

### 6.2 非经典主题主体提取与精灵表契约（2026-09-01 已实施）

宝石、动物、水果、甜点、太空、海洋、春天、节日限定、音乐和交通工具十套非经典主题已按同一流程从旧精灵表重新提取；经典主题不参与本次处理。

- **先选主体，再归一化**：以完整旧精灵表作为输入，通过 Apple Vision 检测前景实例并按逻辑色槽选择主体，不能先按旧 `5×2` 格线裁切。鼓槌、烟花、雨滴、花瓣、风筝尾等分离部件允许合并多个实例或 alpha 连通分量。
- **恢复原图像素**：Vision/连通分量只用于确认哪些像素属于当前主体；输出从原图恢复 RGBA 与原 alpha，避免将推断遮罩直接作为最终边缘而造成描边发虚、透明孔洞丢失或颜色改变。
- **固定单元**：每个主体独立归一化到 `400×400` 透明 PNG，保持比例并居中；可见 alpha 在上、下、左、右均须保留至少 `24px` 安全边。
- **固定图集**：10 个逻辑色槽按行优先重组为 `5×2`，总尺寸必须严格为 `2000×800` RGBA PNG。每槽必须非空，主体及其分离部件不得进入相邻单元。
- **缩放职责**：manifest 的 `tileVisuals.scale` 以 `1` 为运行时基线；只允许未来因整体视觉节奏做明确微调，不能用于修复裁剪、串边或不合规尺寸。提取配置中的槽位 `scale` 只用于离线归一化，并受 `24px` 安全边上限约束，不等同于运行时值。

离线工具与可复核产物位于：

```text
scripts/theme-extraction/
  ThemeExtractor.swift                         # macOS/Vision 批处理工具
  themes.json                                  # 10 套主题、色槽和提取配置
  README.md                                    # 构建、运行和人工覆盖说明
  runs/20260901-all-v1/<theme-id>/              # 本次候选图集、独立槽位、接触表与报告
scripts/validate-theme-assets.js                # 正式资源像素合同校验
tests/theme-assets.test.js                      # 10 套 manifest/正式图集回归测试
```

批处理默认只写入 `scripts/theme-extraction/runs/<run-id>/`，不会直接覆盖 `assets/skins`。候选结果必须先检查带编号接触表和 `report.json`，确认色槽、分离细节、透明边缘与视觉重心，再提升为正式资源。本次替换前旧表已按用户确认移出项目，不再作为项目内备份保留。

## 8. 存档、回退与异常

- 继续使用 `ProgressStore` 的 schema version 2 和 `settings.skinId`；旧存档无该字段时默认为 `classic`。
- 保存了非默认 `skinId` 不代表已经拥有。启动恢复、直接 `SkinService.select()` 和 App action 都检查奖励拥有权；无权或选择写盘失败时保留／回退 `classic`。货币购买与获得主题由独立奖励存档同次提交，下载或应用失败不撤销拥有权。
- `SkinService` 读取到未注册/损坏 ID 时，当前主题立即回退 `classic`，不影响关卡进度；是否回写修正值由实现阶段测试决定，但不得丢失其他存档字段。
- 分包成功后才选择并保存；失败保留当前主题和 `settings.skinId`，清除 pending 后可点击重试。
- 主题资源异步加载沿用现有 generation 检查：旧主题晚到的图片不得覆盖新主题；加载失败使用 manifest/经典回退绘制。
- 每次有效选择递增 `skinLoadRequestId`，仅最新请求允许提交；选择 classic 或已加载主题同样使旧请求过期。无需取消底层下载。
- `setSkin()` 仍同步返回 boolean：有效 ID 已应用或开始加载为 true，非法 ID 未开始操作为 false；内部处理全部异步 rejection。
- `bootstrap` 为 App/Renderer 注入同一个 `SubpackageService`。保存的非经典主题在启动时异步加载，不阻塞首帧，期间保留它的 palette；恢复失败不改存档、不阻断玩法。
- 状态固定为 `idle/loading/loaded/failed`，只在当前 JS 进程内保存，绝不持久化“已下载”。宿主不支持分包时返回 `SUBPACKAGE_UNSUPPORTED`，保持失败状态和基础玩法。
- Renderer 在所有主题图片加载前按完整路径检查 `isAssetReady`；未就绪的分包资源不建立任何图片、失败或 source 缓存。主包预览和 Logo 等继承资源仍可加载。成功提交后调用 `invalidateThemeAssets(themeId)` 并重新加载正式图片，独立的预览缓存保持不变；预览加载/尺寸失败时安全回退。
- 主题切换只影响视觉和语义 token；当前关卡的 `GameRunner` 状态、计时、撤销栈和提示数据必须保持不变。

- `assets/skins/music/music-sprite-sheet.png`：10 个音乐图标，5×2 正方形精灵单元，透明 RGBA；顺序为：深色黑胶唱片/唱盘、白色钢琴键、红色麦克风、橙色鼓、黄色铃铛、绿色吉他、青色耳机、蓝色音符、紫色小号、粉色手风琴。manifest 位于 `src/skins/music.js`，已注册到 `src/skins/index.js`，并复用通用的底砖、切片、分页和持久化协议。
- 音乐主题使用运行时 `tileVisuals.scale: 1`；唱片唱臂、耳机和乐器所需的安全边距已写入规范化素材，从源头消除相邻格碎片。精灵加载失败时使用 10 色 `fallbackColors`；深色黑胶槽采用明亮蓝紫色回退，并可作为描边强调。
