# 版本更新面板

## 当前行为

微信小游戏启动时，若本机尚未确认当前更新标记，主页自动展示更新内容。面板包含新增100关（主线共300关）、四款消除特效和音乐回廊；文案随当前中文／英文设置显示。点击“确定”关闭面板；主页金币左侧的圆圈“i”图标可随时重新打开。

只有确认操作会记录已读标记。启动后未确认、关闭小游戏、取消触摸或点在按钮外均不算已读。已确认的同一版本在重启或前后台切换时不再自动弹出；后续更新标记变化后重新提示。存储失败仍允许关闭和游玩，本次会话不再自动提示，下次启动重试展示。

## 维护与职责

- `src/config/update-notice.js` 声明当前稳定更新 ID 和三个内容条目的顺序。发布新版本时，同时更换 `id` 并更新两份语言目录中的 `update.<条目>.title/body`；仅改文案不改 ID，不会再次自动提示已确认的玩家。
- `src/services/update-notice-service.js` 负责本机确认记录。存储 key 为 `cleared:minigame:update-notice:v1`，格式为 `{schemaVersion:1, releaseId:<id>}`。该记录与账号、关卡、金币及云偏好独立，不上传 CloudBase；缺失、读失败或格式错误按未确认处理。
- 微信组合根 `src/bootstrap.js` 注入服务；`ClearedApp.start()` 在奖励通知之前打开面板，App 编排查看／确认及纯 ViewModel，Renderer 只负责绘制。通用宿主不主动创建该微信本机服务。
- 面板打开期间只允许 `update:confirm`；`home:updates` 是主页入口。底层命中区和进行中的触点会清除，微信原生资料授权按钮暂时卸载；关闭后恢复正常主页交互及待显示的奖励通知。更新内容使用本地随包配置，不新增请求、运行素材或分包。

## 布局与验证

主页入口为48×48触控区，圆圈“i”居中绘制，使用当前主题图标色；沿用顶部栏中心线，与金币保持6像素间隔，极窄视口下放到金币下方。图形采用离线 Reicon 目录中的 `info-circle`（Outline），以现有 Canvas 圆环与线段绘制并统一线宽，无图标字体或图片加载。原始 [SVG](assets/update-notice/reicon-info-circle.svg) 与 [MIT 许可](assets/update-notice/REICON-LICENSE.txt) 留在文档目录，不进入微信包；来源为 [dqev/reicon](https://github.com/dqev/reicon)，目录快照 `80d6547e46bd3074b8d7fe6682f604c6c89d91a8`，上游同时注明 Solar Icons（480 Design，CC BY 4.0）与 Zappicon 的基础图标来源。

公告打开时先清空整张 Canvas，只绘制不透明主题底色，再铺满屏幕的 `strongPanel` 深色层，包括上下安全区；主页图案、金币、操作按钮及状态提示均不绘制，因此没有可以被误认为可操作的背景按钮。公告条目和“确定”按钮绘制在更深一层的结果面板上，关闭后重新绘制完整主页。采用现有 Canvas 绘制，不依赖模糊滤镜支持或截屏缓存。面板按实际文字宽度换行，根据安全区和横屏高度调整字号。

当前限制为三个简短条目，不滚动。新增条目或较长文案前，应增加滚动或分页并补充文字可见性及触控验证，不能仅继续减小字号。

`tests/update-notice.test.js` 覆盖首次展示、确认后重启、更新 ID 变化、手动打开、保存失败回退、遮挡下层操作、双语换行、整屏背景遮挡、纯图标入口与窄屏／高安全区／横屏几何。运行 `node tests/run.js`、`node scripts/check-package-budget.js` 和 `git diff --check`；微信开发者工具编译、实际触控与真机安全区仍须单独验收。

当前120组回归和源码包体检查通过。微信开发者工具普通编译无错误，iPhone 12/13 模拟器已预览圆圈“i”入口与未读版本公告，确认整屏背景隐藏主页图案和操作按钮；首次展示、确认关闭、重启不重复提示及图标重新打开由回归测试覆盖。本轮自动点击未触发模拟器响应，新的入口仍需人工点击复核；真机触控、安全区和客户端上传／发布尚未验收。
