# 本地优先、关键节点云同步

2026-09-07：本轮目标是降低小游戏请求频次、维持离线游玩，不增加防作弊能力。复用现有本地存档和 SyncStore 待发送队列，不另建同步框架，不把已迁移账号退回旧本地余额权威。

## 自动同步时机

| 触发点 | 行为 |
| --- | --- |
| 冷启动 | 本地先启动；异步完成一次身份／云档恢复，失败不阻塞本地入口 |
| 进入关卡、通关、体力消费／返还、偏好修改 | 及时保存本地状态和现有操作记录，不逐次请求 |
| 回到首页、进入账号页 | 有待发送操作时批量同步；没有操作且云状态未超过 5 分钟则不请求 |
| 连续游玩 | 待同步通关累计 5 次、队列累计 40 条，或变更积累满 3 分钟后的下一次本地写入，尝试同步 |
| 切后台 | 先本地保存；有待发送操作才尽力同步，不在后台做空队列刷新 |
| 回到前台 | 有操作或云状态已过期时恢复同步；短暂来回不重复完整身份／读档链路 |
| 账号页手动同步、奖励重试／分享解锁 | 用户明确操作仍立即尝试，保留原有反馈与失败重试 |
| 金币购买 | 若有待结算通关操作，先同步奖励再购买；没有这些操作就直接沿用原购买请求 |

自动同步最短间隔为 60 秒，包括冷启动读档后的这段时间；因此回主页／切后台是尝试点，不承诺每次访问立即上传。触发合并为同一个在途任务。失败后按 60、120、240、300 秒退避，后续自动触发才重试；没有计时轮询或后台重试循环。手动同步绕过自动冷却，但仍复用在途请求。

3 分钟是事件驱动的检查阈值，不是定时备份承诺：若玩家不再产生存档变更，也未经过页面／生命周期触发点，不额外发请求。清理本地数据或换设备前，建议在账号页手动同步并确认“已同步”；后台请求不能作为唯一保档手段。

## 批次、存档和恢复

- 本地存档 key、账号／环境隔离、稳定关卡坐标、operationId、幂等回执及数据域均不变。
- 最后游玩位置和同字段偏好只保留最新非在途意图；已在途 ID 保留到原请求结束。通关、奖励、每日次数和体力事件不合并、不因降频丢弃。
- 沿用最多 200 条待发送操作的上限，不宣称无限期离线；满队列时保留原记录、拒绝无法持久化的新操作。40 条触发点为正常联网时预留容量，不保证断网时不会触顶。
- 每轮仍先读取一次服务端状态和准入结果，再以每批最多 50 条发送，最多连续 4 批，不为每批重复读档。只有明确处理且本地应用落盘的记录才移出队列。
- 部分可重试回执、网络／存储失败会停止本轮，保留未确认记录。同步过程中新增的操作若超过本轮上限，留待后续触发。
- 已有云账号奖励仍显示“奖励待同步”，同步确认后到账。购买先同步待结算奖励；同步失败不继续购买，不把本地快照直接覆盖云钱包。体力继续本地乐观应用，冲突仍按现有轻量服务器快照策略处理。
- 本轮主要减少云函数调用、重复读档及重复偏好操作；不承诺数据库逐事件结算次数或实际费用按相同比例下降。

## 实现与验证边界

- `src/services/progress-sync-service.js`：统一自动节奏、内存冷却／退避、分批发送；重启重新恢复，不依赖持久化计时器。
- `src/services/sync-store.js`：合并最后位置／同字段偏好；保留在途 ID 和所有业务事件。
- `src/app.js`、`src/bootstrap.js`：首页、账号页、前后台和启动触发，以及购买前待到账奖励同步。
- `tests/cloud-checkpoint-sync.test.js`：实际模拟接口请求计数、重启保队列、自动退避／手动重试、101 条跨批发送、部分回执、偏好合并、账号冷却隔离、前后台及购买编排。

运行 `node tests/run.js`、`node scripts/check-release-readiness.js --mode closed` 和 `git diff --check`。Node 模拟不代表微信生命周期和真实网络验收；本轮手机／iPad 尚待验证：连续游玩后回主页、断网并重启再恢复、切后台立即关闭、跨设备读取以及购买前奖励到账。

不修改现有玩家数据，不清缓存，不部署后端，不改变唯一云环境、白名单、内部迁移或 release 开关。若后续要求离线立即可花费金币／直接上传本地余额，需要另行调整存档合并与购买协议，不属于本轮降频。
