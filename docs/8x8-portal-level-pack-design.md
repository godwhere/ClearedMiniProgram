## 1. 章节目标

本章不再连续堆叠传送门，Portal 说明统一为两句共享状态提示。普通关负责
持续检验多色空间规划，Portal 关作为改变拓扑的变化题穿插出现；普通关不是刻意
放低难度的过场。

- 全部 8×8，不增加 Blocked、炸弹、重走或其他新机制。
- 63–67 使用 5–6 色；68–92 使用 6–9 色。
- 93–97 使用 7–9 色，继续双门混排，不改变前 92 关。
- 当前所有章节 Portal 关恰好两个门格，四门网络延后到 100 关以后再教学。
- Portal 标准解每条线路最多传送一次；每关标准解恰好一次传送。
- 所有章节关都不设置逐关 `Instructions`；Portal 进门前使用统一初始说明，LOCKED/WAIT 使用统一到门说明，出口续接后隐藏。
- 允许高成本无门解，但必须排除只改一两条官方线路就能绕开的廉价旁路。

## 4. 出题方法与质量边界

本批从已验证的均衡多线路骨架出发，通过路径尾段重组、合并后重新分段、旋转和
镜像改变端点关系；Portal 题再用两个内部格重组两片区域。它们不是运行时随机题，
也不是把一条超长 Hamilton 路径切成大量短颜色。

68–92 的实际指标：

- 每关 6–9 色；
- 标准线路最短 4 格、最长 15 格，最长占比 23.4%；
- 没有 2–3 格凑数线路，没有相邻同色端点对；
- 9 个 Portal 关全部为双门网络，Portal 所在线路不固定为第一色；
- 与既有 33–67 关及本批内部进行八种旋转/镜像等价检查，没有重复题面；
- 所有标准解均覆盖 64 格并实际回放为 `WON`。

数量和长度只是自动筛选指标，不代替人类试玩。名称中的“中心”“边界”“顺序”
是内部题面主题，不构成新的运行时规则，也不显示在游玩页标题中。

## 5. 无门解审查

63–92 的 14 个 Portal 题中，只有 64、76、84、89 具备无门完整覆盖解。其余十题在当前规则下
的无门搜索结果为 `unsatisfiable`。

高成本旁路的可复现检查不是只保存一条看起来复杂的解，而是：

1. 保留官方解中的所有非待改线路，把它们占用的格视为固定阻挡；
2. 只放开 Portal 线路，搜索无门完整解，必须无解；
3. 再逐一放开 Portal 线路加任意另一色，仍必须无解；
4. 保存至少一条完整无门解并用真实 `GameRunner` 回放。

因此这些题至少需要三种颜色偏离官方布局，才可能不用门完成。这个结论相对于
官方布局成立，不等同于对人类难度或所有解法数量作绝对保证。

- 第 64 关保留的审查示例改动五色，但它并不要求所有无门解都改动五色。
- 第 76、84、89 关的审查示例和一/二色旁路反证由
  [mixed-chapter.test.js](../tests/mixed-chapter.test.js) 固定。

离线工具只支持最多 8×8 的当前四邻接覆盖规则，状态上限 250000；超过上限返回
`limit`，不得把它解释为无解。更大棋盘或新移动规则出现时再升级内容工具。

```sh
node scripts/solve-no-portal.js
node scripts/solve-no-portal.js 84
```

## 后续机制预留（本批不实施）

本章 35 关使用普通规则与 `portal@2` 混排。下面只记录未来机制的设计边界，
不向本批题面、解法、`GameRunner` 或 UI 里埋入未实现字段。

### A. 可重复路径：`retrace@1`

“重复走”需要先区分两种含义：

1. **同一线路自重访**：允许当前线路再次经过自己已经走过的格，建议每格
   设置明确的 `MaxVisitsPerCell` 上限（首版可默认 2），并在解答中显式记录
   重访步骤；
2. **不同线路共享已占格**：这会改变 `owner`、完成判定和撤销语义，应另立
   `shared-path@1`，不能偷偷放宽现有占用规则。

首版 `retrace@1` 仍禁止跨线共享、重复端点和重复 Portal；快照、Undo、
`touchcancel` 与提示搜索必须同时保存/消费访问次数。它不能通过修改
`PortalRulesVersion` 来启用。

### B. 炸弹九宫格：`bomb@1`

建议使用独立题面形状，而不是把 `portal+bomb` 拼成机制字符串：

```js
{
  Mechanic: 'bomb',
  BombRulesVersion: 1,
  Bombs: [{ Id: 'B1', Cell: 27 }]
}
```

首版需要先冻结以下语义：

- 首次合法进入炸弹格时触发，还是松手时触发；
- 炸弹是否一次性消耗；
- 以炸弹为中心向四周裁剪的 3×3 footprint，越界格如何处理；
- 被摧毁格是否变为不可进入、是否从 required coverage 中移除；
- 是否允许摧毁端点、已提交线路、另一枚炸弹。

推荐 `bomb@1` 只允许静态安全 footprint：端点、已有线路和其他炸弹不得
落入爆炸范围；受影响格进入 `destroyedMask` 后不可再走且不计 required
coverage。会切断既有线路、连锁引爆或改变端点的版本另立 `bomb@2`。

炸弹结果必须由纯函数从中心格计算，解答只记录触发步骤和 Bomb ID，不能
信任作者在答案中手写的九宫格数组。爆炸状态、动画锁、Undo、重置、后台
取消和回放都必须原子一致。

### C. 组合机制与施工顺序

第一次需要 Portal、重复路径和炸弹组合时，再引入显式：

```js
{
  Mechanics: [
    { Id: 'portal', RulesVersion: 2 },
    { Id: 'retrace', RulesVersion: 1 }
  ],
  CompositionVersion: 1
}
```

组合必须有兼容矩阵和确定的事件顺序；未知机制、版本或组合在发布校验中
直接拒绝，运行时对坏数据安全降级但不能执行内容携带的脚本。

推荐施工顺序：

1. 先完成本章 35 个混合关卡的 UI、提示、发布校验和真机验收；
2. 单独实现并验证 `retrace@1` fixture；
3. 单独实现并验证 `bomb@1` fixture；
4. 最后再评审组合机制和新的解答事件流。

### 设计重点

- **93 折巷分流**：上侧长线与左侧折巷分配空间，下侧两线交错封口；避免直接沿最外圈封死内侧余格。
- **94 隔层换岸**：第 3 色通过右侧两门跨层，第 1 色沿门内侧连接；中央第 2 色和左侧第 5、7 色共同分配余格。
- **95 内外套接**：第 4 色穿行上方内层，第 6 色沿右侧绕接，第 7 色回收底部；不能把内外区域分别机械直连。
- **96 九色锁扣**：中心第 2、3、8 色均为 5 格有效线路，外围第 6、7、9 色承担绕接；高端点密度下仍无相邻同色端点或凑数短线。
- **97 双岸合围**：第 5 色连接右上与上缘门格，第 7 色贯穿中右部，其余线路完成左右和底部区域分配；所有线路为 5–10 格。

候选从既有均衡多线路解出发，以端点移接和局部路径重组改变各色区域，再接入双门；
不是切分单条全盘长蛇，也不是仅旋转、镜像或换色复制旧题。候选生成只用于离线设计，
最终题面和解答固定提交，不增加运行时生成器或新依赖。静态题面/解答图已核对，
以上为设计意图，不据此宣称真实人类难度或唯一解。

标准解均覆盖 64 格，线路最短 5、最长 14，最长占全盘 21.9%。
94 与 97 的标准解分别只有第 3、第 5 色进行一次传送；禁用门格后的精确覆盖搜索均为
`unsatisfiable`，不是触及上限的 `limit`。两题无需可选旁路见证。
正式回归还检查八种对称去重、标准/反向/变序实际 Runner 回放和完整提示。
