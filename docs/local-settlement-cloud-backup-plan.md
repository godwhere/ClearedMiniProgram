# 本地结算＋偶尔云备份：未上线小游戏实施方案

2026-09-07 修订。状态：P1、P2 与 P3 可在本地完成的实现已落地；线上配置、部署和手机预览仍未改变，以下是代码合同，不代表已上线能力。

## 1. 正确前提与范围纠正

游戏尚未上线。需求是本地顺畅游玩、减少后端请求，允许玩家修改自己的游戏数据；云端只是换机／重装时可用的一份备份，不负责逐关发奖或游戏币购买。

旧方案中的 4096 日约 11.2 年历史是人为构造的压力样本，不是现有玩家数据；“当前＋上一版＋首次基线”的多版本归档也是代理额外加入的设计，不是用户需求。此前 3,129,375 字节的结果描述的是该合成样本的每日原始存档，不代表当前存档已超限。

本修订替代旧版 P0–P4、原第 11 节的停线结论和分块申请，不再等待分块授权，也不以完整多年历史恢复作为实施门槛。测量作为旧假设的记录，不撤销基本容量检查，更不能用它证明真实玩家已有多年数据。

首版明确不做：本地历史分块、大备份分块传输、玩家历史版本库、完整每日明细云归档、多设备自动合档、面向大量已上线老版本玩家的迁移系统。现有开发测试存档不清除，既有后端数据不删除。

## 2. 玩家能感知的结果

| 场景 | 目标行为 |
| --- | --- |
| 普通／每日通关 | 按现有配置在本机结算；本地保存成功立即显示奖励，不等网络、不需点击领取 |
| 重复通关／重复点击 | 依靠已领取标记去重，不重复发首通金币 |
| 游戏币购买 | 本地检查余额与所有权，扣款和获得物品一起保存，离线可用 |
| 体力、进度、设置 | 按现有规则本地更新和保存，不逐次请求 |
| 网络失败 | 已保存的进度、金币和物品照常可用；稍后备份 |
| 本地保存失败 | 保留恢复依据，显示“本地保存未成功，点击重试”，不能假报到账或购买成功 |
| 主页／账号页 | 本地保存状态与云备份状态分开，云端未更新不再显示成“奖励待同步” |

奖励额度、物价、体力规则、每日完成条件、广告／分享准入不变。仍需防串档、重复结算和保存失败；不增加反作弊验证。

当前旧云结算预览的展示过渡：普通／每日结果页不再显示“奖励待同步”，等待回执时展示配置中的首通奖励额度，确认到账后显示实际获得金额；本地保存失败保留重试。此展示调整不修改余额或发奖权威，也不代表新备份模式已启用。

本机尚未上传的数据无法保证在卸载、清缓存或丢失设备后找回。账号页提供“立即备份”和“恢复云备份”；没有历史版本选择或复杂冲突面板。

## 3. 云端只保存恢复游玩所需的当前状态

沿用现有服务和本地 key，不重做本地存储系统。快照不是把所有 storage key 原样上传。

| 内容 | 唯一业务所有者 | 备份边界 |
| --- | --- | --- |
| 普通进度 | `ProgressStore` | 稳定关卡坐标、完成记录、最佳时间、继续游戏位置 |
| 金币、领奖标记与已拥有物品 | `RewardUnlockService` | 实际余额、普通／每日已领取标记、已拥有主题／特效；不按通关数推算金币 |
| 当前每日挑战 | `DailyProgressStore` | 按游戏现有上海日期口径，快照创建当天的挑战标识、进入／完成状态及当前次数所需的去重信息 |
| 当前体力 | `StaminaService` | 余额、恢复基准、解锁／返还标记，不在导出时额外消费或发放 |
| 当前设置 | `PreferencesService` 及现有持久化源 | 主题、特效、声音等现有云设置字段 |

每日历史的具体进入流水、旧日期逐关成绩等不纳入首版云备份；本机已有明细保持不动。每日领奖标记仍保存，不能以“不备份历史明细”为由删掉奖励去重依据。

恢复一个旧日期创建的快照时，该日挑战状态不能冒充今天；今天按现有规则进入新挑战。保留在本机、但未被选中快照覆盖的旧明细，不能被当成新证据再次补发金币。恢复只还原快照中的资产，不额外结算历史奖励。

身份凭据、头像授权、广告凭证、行为日志、图片缓存、Hint 临时状态和域外本地设置不上传、不清除；当前次数中的既有授权去重信息只是已获得状态，不作为一条新广告完成事件重放。

首版使用单快照：快照预算 256 KiB，单次新协议请求／响应预算 288 KiB，按 UTF-8 序列化字节验证，含封装余量；这是项目预算，不是宣称平台上限。用当前 137 关、当前挑战、资产与领取标记验证往返及边界拒绝，不再要求恢复 4096 日明细。超限明确提示备份失败并保留本地，不截断存档、不自动引入分块。仅在真实常规存档或已批准新增内容触及预算时，凭具体数据提出容量改动。

## 4. 何时请求：只在少量明确节点

自动备份冷却定为 3 分钟：距最近一次备份尝试（包括手动）满 3 分钟才允许自动尝试，不是每 3 分钟运行一次的定时任务。手动操作可绕过冷却。

| 触发点 | 请求行为 |
| --- | --- |
| 有有效本地档的启动 | 立即加载本地；身份可异步确认，不自动下载云快照覆盖本机 |
| 本地确实不存在存档 | 身份确认后读取一次最新备份；读取失败不等于“云端无档”，保留重试机会 |
| 进入关卡、通关、购买、连续游玩、修改设置 | 只保存本地／标记变化，零存档与结算请求；不再累计 5 关或 40 次操作触发上传 |
| 回主页／进入账号页 | 有变化且备份冷却结束，尝试一次上传；无变化不读、不上传 |
| 切后台／回前台 | 保存／恢复本地，不单独发起云备份；回到主页仍按上一行判断 |
| 账号页手动备份／恢复 | 明确操作才立即尝试；重复点击共用一个在途任务 |

正常已登录的一次备份只调用一次 `backup.commit`，没有预先 `state.read`，没有逐事件结算。身份初始化、首次空档恢复和用户主动读取分别计数，不藏在“一个请求”的口径里。失败等下一个合格节点或手动重试，不轮询、不立即循环重试；冷却按账号隔离。

本地没有存档但云读取失败时可继续本地开始游戏，不过不能把这份新档自动覆盖未知云档；后续以第 5 节的版本比较保护原云备份。

## 5. 最小后端：两个接口、一份最新备份

沿用现有可信微信身份和 `player-state-api`，新增两个 action，旧结算接口不改名、不借用。

- `backup.read`：读取当前账号的最新快照及版本；明确区分不存在、失败与成功。
- `backup.commit`：提交完整快照；按基础版本比较后替换最新备份，返回确认，不发奖、不扣款。

新增私有集合 `player_backups`，每个账号一条最新快照记录，字段限于 schema、账号绑定信息、云版本、最后请求 ID、保存时间和快照内容。没有上一版本、首次基线、分片、永久回执表或 `backup.activate`。云版本只用于阻止旧请求覆盖新快照，不意味着保存多份版本。

服务器依据可信调用身份定位玩家，校验 App／环境／绑定、结构和容量；不能让客户端指定任意玩家写入。新增默认关闭的备份写入开关，沿用现有账号准入，不自动改变线上权限。

同一请求 ID、相同内容重复到达，只确认一次；同 ID 不同内容拒绝。基础版本落后返回冲突，不自动覆盖，不取金币最大值或相加。客户端只需提示云端另有存档：继续本地玩，或在账号页明确选择覆盖云备份／恢复云备份；不建设自动合档系统。

已有本地档时，云读取结果只能用于明确的恢复操作。恢复前确认会替换哪些当前数据；等待期间本机发生新变化则重新确认。覆盖云端同样使用刚确认的基础版本，再次冲突则停止，不无限强推。

## 6. 必须保留的少量正确性保护

1. 完成记录先落盘；金币与领取标记在同一次资产写入里提交。购买扣款和所有权也一次提交。失败可按准确的已持久化证据重试，不能从余额增加推测本关已经发奖。
2. 每次上传固定一份已保存快照和本地版本。上传时继续玩，旧确认不得清除之后的新变化，且不能把旧余额写回本机。
3. 业务保存成功、备份脏标记保存失败时，启动／检查点可从已持久化状态重新判断是否需要备份，不把未保存内存上传成可靠数据。
4. 多个本地 key 的恢复复用现有应用日志机制：先可靠保存一条恢复任务，再逐域应用，完成后清除任务；失败可重启继续，不开放半恢复资产。这是一次操作的恢复日志，不是玩家历史版本库。
5. 所有异步回调验证账号、环境、绑定和当前本地模式；切换到新模式后，旧结算回执不能再覆盖资产。关闭联网只暂停备份，不能切回旧云余额权威。
6. 切换当前开发测试账号前，核对旧待发送操作、购买与应用日志。已有待办用现有恢复路径确定结果，不清队列、不自动补币；只有实际存在的不一致才需要处理该测试档，不为假设中的老玩家设计批量迁移。

客户端新增明确的 `local-backup` 模式，复用原本地结算能力；不把已有绑定伪装成从未联网的旧游客模式。新模式不调用 `sync.push`／`economy.purchase` 来结算业务。旧预览客户端只认识旧账本，新备份独立存放；本次不重写旧账本服务，也不保证旧预览包能够消费新协议。

## 8. 与当前需求相称的验收

- 飞行模式首通：保存成功即显示获得金币，重启仍在；重复过关不再发首通奖励。每日完成、体力和游戏币购买同样离线成立。
- 连续通关、购买、设置修改不产生存档／结算请求；3 分钟内反复回主页／账号页不重复自动上传；无变化零请求。
- 正常已登录的一次手动／合格自动备份只调用一次 `backup.commit`；失败保留本地，重试不会重复发奖。
- 上传中继续游玩，旧 ACK 不清除新变更、不改回旧余额。账号／环境不一致的响应不应用。
- 当前内容快照往返、边界大小和非法数据拒绝正确；不要求保留或恢复多年逐日明细。
- 空本地档正确恢复；读取失败不当成无云档；非空本地档不自动覆盖。手动恢复中途失败能重启继续，不能开放半份资产或从未选中的旧明细补奖。
- 两设备同时保存，较旧基础版本不能覆盖已更新的云备份；用户明确选择后再操作，不自动合并金币。
- 现有开发测试档及未提交修改保持；无实际待办时不能凭空创建一个老玩家迁移项目。
